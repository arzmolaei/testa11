# رویش — فضای کار سئو

یک برنامه فارسی و راست‌به‌چپ برای مسیر کامل سئو: تحقیق کلمات، نقشه صفحات، سئوی صفحه، تولید محتوا و بررسی نتایج. داده‌ها با شناسه پایدار نگهداری می‌شوند؛ مرتب‌سازی و فیلتر، تصمیم‌های دستی را جابه‌جا نمی‌کنند. رابط با React، TypeScript و Vite ساخته شده و روی Cloudflare Workers اجرا می‌شود.

## نصب خودکار در ویندوز

در Windows 10/11 نسخهٔ ۶۴بیتی، فایل `Install-Rooyesh.cmd` را باز کنید. نصب‌کننده در صورت نیاز Node.js را بدون دسترسی Administrator آماده می‌کند، وابستگی‌ها را نصب و برنامه را آزمایش می‌کند، مرورگر را برای ورود رسمی Cloudflare باز می‌کند و پس از تأیید شما، دیتابیس، جدول‌ها، رمز برنامه و انتشار Worker را انجام می‌دهد. ساخت یا کپی API key لازم نیست.

اگر به دریافت ZIP دسترسی ندارید، یک فرمان در CMD می‌تواند نصب‌کننده و پروژه را از GitHub دریافت کند. روش اجرا، مراحل ورود و رفع خطا در [راهنمای ویندوز](WINDOWS-SETUP.md) آمده است. اجرای دوبارهٔ همان نسخه، اطلاعات انتشار قبلی را نگه می‌دارد. نصب‌کننده پلن حساب را تغییر نمی‌دهد.

## شروع سریع

Node.js نسخه 22 یا جدیدتر و npm لازم است. فرمان‌ها را داخل پوشه‌ای اجرا کنید که package.json دارد؛ در این محیط مسیر /workspace/testa11 است و روی رایانه خودتان همان پوشه بازشده از ZIP را استفاده کنید.

```bash
npm ci
npm run dev
```

در این حالت داده‌ها در IndexedDB همین مرورگر ذخیره می‌شوند و به حساب یا سرویس خارجی نیاز ندارند. خروجی JSON یک پشتیبان کامل قابل بازیابی است؛ خروجی Excel برای بررسی یا انتقال داده‌ها به ابزارهای صفحه‌گسترده است. قبل از پاک‌کردن داده‌های مرورگر، تعویض دامنه یا جابه‌جایی دستگاه، پشتیبان JSON بگیرید. نمونه‌های آموزشی داده واقعی یا پیش‌بینی سئو نیستند.

```bash
npm test
npm run build
```

این فرمان‌ها آزمون‌های منطق برنامه و API، بررسی TypeScript و ساخت نسخه انتشار را اجرا می‌کنند. برای محیط‌های بعدی از همین checkout استفاده کنید؛ نیازی به ساخت Git worktree نیست. پردازش‌های سرور باید در هر محیط تازه دوباره اجرا شوند.

## انتشار روی Cloudflare در شش مرحله

به حساب Cloudflare با دسترسی Workers و D1 نیاز دارید. برنامه بدون اتصال ابری هم قابل استفاده است؛ تا انجام این مراحل، ذخیره بین دستگاه‌ها فعال نیست.

**۱. ورود به حساب خودتان**

```bash
npx wrangler login
```

این فرمان ورود امن Cloudflare را در مرورگر باز می‌کند. رمز یا توکن Cloudflare را داخل فایل‌ها یا گفتگو قرار ندهید.

**۲. ساخت پایگاه داده**

```bash
npx wrangler d1 create seo-studio-db
```

مقدار `database_id` چاپ‌شده را در بخش `d1_databases` فایل `wrangler.jsonc` جایگزین شناسه صفر کنید. نام binding باید `DB` بماند. شناسه صفر فقط برای توسعه محلی است.

**۳. ساخت جدول‌های واقعی**

```bash
npx wrangler d1 migrations apply seo-studio-db --remote
```

**۴. تعیین رمز ورود فضای ابری**

```bash
npx wrangler secret put APP_PASSWORD
```

وقتی ابزار درخواست کرد، یک رمز منحصربه‌فرد و قوی وارد کنید؛ حداقل ۱۲ نویسه و ترجیحاً ۲۰ نویسه یا بیشتر. رمز به‌صورت Secret در Cloudflare ذخیره می‌شود و داخل کد یا خروجی frontend نیست. تغییر این Secret نشست‌های قبلی را بی‌اعتبار می‌کند.

**۵. ساخت و انتشار**

```bash
npm run deploy
```

Wrangler نشانی واقعی `workers.dev` را پس از انتشار موفق چاپ می‌کند. برنامه و API از یک دامنه ارائه می‌شوند؛ پیکربندی CORS یا سرور جداگانه لازم نیست. در صورت تمایل می‌توانید بعداً دامنه اختصاصی را از داشبورد Cloudflare اضافه کنید.

**۶. اتصال و بررسی ذخیره**

نشانی منتشرشده را باز کنید، از تنظیمات برنامه به فضای ابری وارد شوید و وضعیت اتصال را بررسی کنید. یک ویرایش کوچک ذخیره کنید، صفحه را دوباره باز کنید و باقی‌ماندن آن را بررسی کنید. اتصال ابری با انتخاب آگاهانه انجام می‌شود؛ تا پیش از اولین ذخیره ابری، از نسخه محلی پشتیبان بگیرید. محدودیت‌ها و مصرف D1/Workers را از داشبورد حساب خود بررسی کنید.

## آزمایش کامل Cloudflare روی دستگاه خودتان

این حالت Worker و SQLite محلی را اجرا می‌کند؛ به حساب Cloudflare نیاز ندارد.

```bash
cp .dev.vars.example .dev.vars
```

فایل `.dev.vars` را باز کنید و مقدار نمونه را با رمز آزمایشی خودتان عوض کنید. این فایل در Git نادیده گرفته می‌شود. سپس:

```bash
npx wrangler d1 migrations apply seo-studio-db --local
npm run cloud:dev
```

پس از آماده‌شدن سرور Wrangler، برنامه از همان سرور به API متصل می‌شود. اجرای معمول `npm run dev` فقط frontend و ذخیره محلی مرورگر را فراهم می‌کند. داده SQLite محلی و داده D1 منتشرشده مستقل هستند؛ گزینه `--remote` را فقط برای پایگاه داده حساب خودتان به کار ببرید.

## ایمنی داده و قرارداد API

ذخیره محلی مرورگر و ذخیره ابری دو محل مستقل‌اند. همگام‌سازی، سرویس تحلیل زنده Google یا گرفتن آمار ابزارهای پولی نیست؛ مقادیر Search Volume، KD و Search Console از داده‌هایی که وارد می‌کنید می‌آیند. نرمال‌سازی فارسی فقط برای تطبیق فنی است و معنی یا نیت کلمات را ادغام نمی‌کند. رکورد تکراری بدون تصمیم کاربر حذف نمی‌شود.

فضای ابری یک فضای مشترک با یک رمز است؛ پنل چندکاربره، نقش‌های دسترسی یا حساب‌های جداگانه ندارد. هر کسی که این رمز را داشته باشد به تمام پروژه‌های این فضای ابری دسترسی دارد. خروج از حساب کوکی همین مرورگر را پاک می‌کند؛ برای بی‌اعتبارکردن همه نشست‌ها، Secret رمز را تغییر دهید.

نشست HTTPS با کوکی `HttpOnly; Secure; SameSite=Lax` به مدت هفت روز نگهداری می‌شود. درخواست‌های نوشتن از دامنه دیگر رد می‌شوند. حدس‌زدن رمز به ۱۰ تلاش در ۱۵ دقیقه برای هر IP محدود است. داده API فقط پس از ورود خوانده یا نوشته می‌شود. پاسخ‌های خطا جزئیات پایگاه داده یا رمز را افشا نمی‌کنند.

| درخواست | رفتار |
| --- | --- |
| `GET /api/status` | `{configured, authenticated}`؛ بدون افشای داده پروژه |
| `POST /api/login` | JSON با `password`؛ ایجاد کوکی ورود |
| `POST /api/logout` | پاک‌کردن کوکی ورود |
| `GET /api/state` | `{state, revision}`؛ در فضای تازه `state: null` و `revision: 0` |
| `PUT /api/state` | JSON با `{state, revision}`؛ پاسخ `{revision}` پس از ذخیره |

اگر دو دستگاه یک نسخه را ویرایش کنند، ذخیره دوم با `409 REVISION_CONFLICT` متوقف می‌شود تا نسخه جدید بدون هشدار بازنویسی نشود. فضای ابری هر وضعیت را به قطعه‌های UTF-8 کمتر از ۹۰۰ کیلوبایت تبدیل می‌کند و تغییر اشاره‌گر نسخه را در تراکنش D1 انجام می‌دهد. هر ذخیره حداکثر ۲۵ مگابایت است؛ این طراحی از محدودیت ۲ مگابایتی هر ردیف D1 عبور نمی‌کند و درخواست ذخیره زیر سقف ۵۰ کوئری D1 باقی می‌ماند. چند snapshot اخیر برای پاک‌سازی امن نگهداری می‌شود، اما جای پشتیبان مستقل را نمی‌گیرد.

**پلن رایگان Workers برای فضای ابری کوچک مناسب است.** محدودیت CPU آن ۱۰ میلی‌ثانیه برای هر درخواست است؛ خواندن، اعتبارسنجی و ذخیره snapshot بزرگ می‌تواند از این سقف عبور کند. برای ذخیره ابری مجموعه‌های بزرگ، مثل ۲۰٬۰۰۰ کلمه با یادداشت‌های طولانی یا فایل نزدیک ۲۵ مگابایت، پلن Workers Paid با سهمیه CPU کافی لازم است. سقف ۲۵ مگابایت حد پذیرش برنامه است و تضمین عملکرد روی پلن رایگان نیست. ظرفیت محلی مرورگر از این محدودیت Cloudflare مستقل است.

حجم کار هدف حدود ۲۰٬۰۰۰ کلمه، ۲٬۰۰۰ صفحه و ۲٬۰۰۰ محتوای کوتاه است. مرورگر، طول متن رکوردها، فضای دستگاه و سهمیه Cloudflare روی ظرفیت واقعی اثر دارند. ورود داده باید پیش از تأیید بررسی شود؛ نگهداری پشتیبان JSON دوره‌ای توصیه می‌شود.

## رفع مشکل

- **اتصال ابری پیکربندی نشده:** binding `DB` و Secret `APP_PASSWORD` با حداقل ۱۲ نویسه را بررسی و دوباره منتشر کنید.
- **`SERVICE_UNAVAILABLE`:** جدول‌ها باید با migration ساخته شده باشند. اتصال D1 و سقف مصرف حساب را بررسی کنید؛ این خطا جزئیات داخلی را به مرورگر نمی‌فرستد.
- **`REVISION_CONFLICT`:** پیش از بارگذاری نسخه جدید، از تغییرات محلی پشتیبان بگیرید. ذخیره کورکورانه با نسخه قدیمی انجام نمی‌شود.
- **`TOO_MANY_ATTEMPTS`:** تا ۱۵ دقیقه صبر کنید و رمز درست را از محل امن خودتان بررسی کنید.
- **ذخیره مرورگر ناموفق:** فضای دیسک، حالت خصوصی مرورگر و مجوز نگهداری داده سایت را بررسی و فوراً پشتیبان JSON دانلود کنید.

فایل‌های تولیدشده، `.dev.vars` و `.wrangler` نباید وارد Git شوند. برای انتشار واقعی باید مراحل حساب خودتان انجام شود؛ اجرای build یا آزمایش محلی، انتشار روی اینترنت محسوب نمی‌شود.

## امکانات روزانه

- چند پروژه مستقل با راهنمای مرحله فعلی و اقدام بعدی.
- کلمات: جستجو، فیلتر، مرتب‌سازی، صفحه‌بندی، انتخاب گروهی، تصمیم و گروه‌بندی؛ تکرارهای فنی فارسی فقط علامت می‌خورند.
- ورود CSV/TSV/Excel با نگاشت ستون و پیش‌نمایش: تطبیق با خود کلمه، نه ترتیب سطرها. نیت و سختی دستی از داده ابزار جدا می‌مانند.
- صفحات: پنل هدف‌گذاری و ماژول‌های بازشونده SERP، سئوی داخلی، بریف، لینک‌سازی، چک‌لیست فنی و انتشار.
- محتوا: جدول و تقویم سبک، بریف، مسئول، تاریخ انتشار و ارتباط ثابت به صفحه.
- نتایج: آمار واقعی واردشده، مقایسه دوره قبل و پیشنهاد اقدام؛ رتبه و ترافیک پیش‌بینی نمی‌شوند.
- خروجی Excel با دقیقاً شش شیت و بخش‌های پیشرفته جمع‌شده؛ CSV کلمات؛ JSON قابل بازیابی همه پروژه‌ها.
- ذخیره خودکار محلی، تا ۸ نسخه قبلی، تأیید حذف، هشدار تغییرات ذخیره‌نشده و جلوگیری از ویرایش همزمان در دو تب.

در صورت خرابی داده محلی، برنامه آن را با نمونه جایگزین نمی‌کند؛ ویرایش متوقف می‌شود و داده خام قابل دانلود است. بازیابی یک پشتیبان معتبر، نسخه خراب را جداگانه حفظ و حافظه را ترمیم می‌کند. پرشدن حافظه یا قطع ناگهانی دستگاه همچنان می‌تواند مانع آخرین ذخیره شود؛ وضعیت ذخیره را بررسی و پشتیبان مستقل نگهداری کنید.

## نصب روی موبایل و استفاده آفلاین

روی نسخه منتشرشده با HTTPS، پس از بارگذاری کامل، فایل‌های رابط و فونت‌ها در Service Worker ذخیره می‌شوند. از گزینه Install در مرورگر یا Add to Home Screen استفاده کنید. برنامه پس از قطع اینترنت قابل بازشدن است؛ API و داده‌های خصوصی ابری در کش Service Worker ذخیره نمی‌شوند. ذخیره آفلاین در IndexedDB انجام می‌شود. اگر همگام‌سازی را قبلاً فعال کرده باشید، با برگشت اتصال، داده‌های در انتظار ارسال می‌شوند؛ اختلاف نسخه به‌جای بازنویسی پنهانی گزارش می‌شود.

در نسخه توسعه `npm run dev` کش آفلاین فعال نیست. برای بررسی آفلاین از `npm run build` و `npm run preview` یا اجرای Worker محلی استفاده کنید. در اولین استفاده بدون اینترنت، هنوز فایل‌های برنامه در دستگاه وجود ندارند. پاک‌کردن حافظه سایت، حالت خصوصی مرورگر و تغییر دامنه می‌تواند داده محلی را حذف یا جدا کند.

## اجرای بررسی‌های مرورگر

Chromium و Playwright لازم‌اند. این محیط Chromium را در `/usr/bin/chromium` دارد. اگر روی دستگاه شما مسیر متفاوت است، `CHROMIUM_PATH` را برای `test:browser` تعیین کنید. ابتدا نسخه انتشار را بسازید و در یک ترمینال اجرا کنید:

```bash
npm run build
npm run preview -- --port 4173
```

در ترمینال دیگر:

```bash
npm run test:browser
npm run test:performance
node scripts/recovery-check.mjs
npm run workbook
```

بررسی مرورگر پروژه‌های آزمایشی را در مرورگر مستقل می‌سازد؛ داده‌های مرورگر شخصی شما را دست‌کاری نمی‌کند. آزمایش ظرفیت ۱۰۰، ۱٬۰۰۰، ۱۰٬۰۰۰ و ۲۰٬۰۰۰ کلمه را بررسی می‌کند. فایل‌های خروجی آزمایش زیر `artifacts/` ساخته می‌شوند و در Git نیستند. خروجی `npm run workbook` یک فایل آماده Excel در همین پوشه است.

برای آزمایش همگام‌سازی از یک دیتابیس **محلی آزمایشی** استفاده کنید، Worker را روی درگاه 8787 اجرا کنید و سپس:

```bash
CLOUD_TEST_VARS=.dev.vars npm run test:cloud-browser
```

این آزمایش عمداً نسخه ابری را جایگزین می‌کند و اختلاف نسخه می‌سازد؛ هرگز آن را به دیتابیس اصلی یا آدرس انتشار‌یافته هدایت نکنید. `.dev.vars` را وارد Git یا بسته انتشار نکنید.
